# مِرصاد المستودع

تطبيق Android (Expo / React Native) لمراجعة فواتير التجهيز بالباركود دون اتصال. يعمل بالكامل على الجهاز: قاعدة SQLite محلية، ولا يُرسل أي ملف أو سجل إلى الإنترنت.

## سير العمل

1. **استيراد** ملف Excel (XLSX/XLS/CSV) بخمسة أعمدة: `رقم الطلب | رقم الفاتورة | كود الصنف | الوحدة | الكمية`. تُعرف الأعمدة من العناوين (عربي/إنجليزي) أو بالترتيب الافتراضي، ويمكن تعديل الربط. الأسطر المعيبة تُستبعد مع عرض سببها ولا تمنع استيراد الباقي.
2. **الاستخلاص:** تُستخلص الفواتير والبنود من الجدول باستعلامات SQL (Views في `lib/core/engine.ts`): `v_orders` ثم `v_items` ثم `v_item_progress` ثم `v_invoice_stats`. الأسطر المتكررة لنفس الصنف داخل الطلب تُجمع.
3. **المسح** (قارئ خطي HID):
   - مسح **رقم الطلب** من البوليصة يفتح فاتورته (ويُقبل رقم الفاتورة أيضاً).
   - مسح **كود صنف**: مقبول، أو **تجهيز زائد** إن تجاوز الكمية (يُسجَّل ويُسمح به)، أو **خطأ تجهيز** إن لم يكن في الفاتورة.
   - أي كود أطول من **10 خانات** ليس كود صنف (يُعامل كرقم طلب، وإن لم يوجد سُجّل «مسح غير مرتبط»).
   - **إنهاء الفاتورة** يتطلب اكتمال كل الأصناف؛ **الترحيل** يسمح بتركها بنواقص لاستكمالها لاحقاً (بإعادة مسح بوليصتها). مسح بوليصة أخرى يُقفل الحالية إن اكتملت ويرحّلها إن بها نواقص.
4. **التقدم:** لوحة العمل تعرض إجمالي الفواتير والمنتهية والمتبقية والمرحّلة مع رسم خطي، وكل فاتورة لها نسبة تقدم = الوحدات الممسوحة ÷ إجمالي الوحدات.
5. **التقرير:** أخطاء التجهيز والتجهيز الزائد والنواقص المرحّلة والمسحات غير المرتبطة، قابل للطباعة (أو الحفظ PDF من نافذة الطباعة) أو المشاركة كنص.

## ملاحظات

- مفتاح المقارنة للأكواد يتجاهل الأصفار البادئة والأرقام العربية والمسافات.
- إعادة استيراد طلب بدأت مراجعته لا تستبدله (يُتخطى ويُبلَّغ عنه)؛ «بدء دفعة جديدة» في لوحة العمل يمسح كل شيء.
- الصنف الواحد بوحدتين مختلفتين في الطلب نفسه يُجمع كصنف واحد (المسح لا يميز الوحدة).

## التطوير والاختبار

```bash
pnpm install
pnpm exec tsc --noEmit
pnpm exec vitest run tests/engine tests/importer tests/xlsx tests/base64 tests/report
```

اختبارات المحرك تعمل على SQLite حقيقية (`node:sqlite`، يلزم Node 22.13+).

## البناء (GitHub Actions)

- **Check and build Android APK** (مع كل دفع إلى `main`): فحص الأنواع، الاختبارات، حزمة JS، ثم بناء APK وإرفاقه كملف `marsood-apk`. التوقيع تجريبي (مفتاح debug)؛ للنشر على Google Play يلزم مفتاح توقيع خاص.
- **E2E on Android emulator** (يدوي): يبني نسخة x86_64 ويشغّلها على محاكي لوحي، يختار ملف Excel من منتقي الملفات الحقيقي، ويحاكي القارئ الخطي بإدخال لوحة مفاتيح (Enter / Tab / بلا منهٍ) ويتحقق من قواعد المسح والترحيل والتقرير (`e2e/run_e2e.py`).
